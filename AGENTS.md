# Release (Flutter app in `mobile/`)

- GitHub `main` of the release repo can hold work this project lacks (it is the store source of truth); before any sync, diff the snapshot against the remote tree and merge newer remote media/content first, because the sync's `rsync --delete` would otherwise silently roll back shipped films.
- Release repo `pranacodes-cmyk/tai-chi-flow` maps this project's `mobile/` contents directly to its root (no `mobile/` prefix). Sync snapshots with `sync-source.yml` after remote diff, and include `mobile/.github` in the snapshot tarball (the sync's `--delete` otherwise wipes the workflows); preserve remote workflows and update them via Contents API only when required. `release.yml` runs Flutter analyze/tests, signed AAB → Play internal, IPA → TestFlight; build number = 1000 + run number. Signing stays in GitHub secrets. Only bundled onboarding/UI/breath voice moves into `android/voice_pack`; lesson media stays on R2, so pack validation must not require the former 1,000+ lesson clips. iOS uses a dedicated development identity and App Store Connect cloud export signing to avoid shared certificate revocation. Sandbox APKs use the persistent private-metadata upload key, never the reset-prone debug key.
- Every iOS privacy manifest must have NSPrivacyTracking match its NSPrivacyTrackingDomains (true only with domains, false only without), because Apple's ITMS-91064 rejects both mismatches; the app's own manifest lists Meta's tracking domain, `Podfile` patches SDK manifests, and `release.yml` re-checks every manifest in the archive and fails before upload on any mismatch.
- Ad measurement goes only through `mobile/lib/services/tracking_service.dart` / `src/lib/tracking.ts`, gated by `adsMeasurementAllowed` (on by default in every country with a Profile opt-out, by the owner's explicit choice; iOS waits for ATT; country = store account country via RevenueCat storefront through `adsCountry`, phone region only as fallback, because phone region settings misplace many users); the choice lives only in Profile (no launch sheet); Meta SDK auto-init/auto-logging stay off in native manifests and ad-ID collection is enabled only at runtime once allowed, while Android keeps the standard attribution plumbing (AD_ID permission, ads-identifier + install-referrer libs, Facebook/Instagram `<queries>`) and events flush immediately; no onboarding, health or practice data is sent, because consent and Meta's health-data rules require it.
