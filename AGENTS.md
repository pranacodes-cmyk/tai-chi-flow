# Release (Flutter app in `mobile/`)

- GitHub `main` of the release repo can hold work this project lacks (it is the store source of truth); before any sync, diff the snapshot against the remote tree and merge newer remote media/content first, because the sync's `rsync --delete` would otherwise silently roll back shipped films.
- Release repo `pranacodes-cmyk/tai-chi-flow` maps this project's `mobile/` contents directly to its root (no `mobile/` prefix). Sync snapshots with `sync-source.yml` after remote diff; preserve remote workflows and update them via Contents API only when required. `release.yml` runs Flutter analyze/tests, signed AAB → Play internal, IPA → TestFlight; build number = 1000 + run number. Signing stays in GitHub secrets. Only bundled onboarding/UI/breath voice moves into `android/voice_pack`; lesson media stays on R2, so pack validation must not require the former 1,000+ lesson clips. iOS uses a dedicated development identity and App Store Connect cloud export signing to avoid shared certificate revocation. Sandbox APKs use the persistent private-metadata upload key, never the reset-prone debug key.
